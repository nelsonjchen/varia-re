# Open-to-connect and screen polish — v0.9.0 / 15

## Intent and design

User wants opening the app to connect, less default-looking bottom buttons, and
no persistent app name header. Applied the local anti-ai-slop-design skill.
Brief: cyclist opens the app to monitor approaching traffic; radar health/threat
must attract attention first, Pause/Resume is the primary action, configuration
is secondary. Visual direction: a dark cycling instrument with clear radar
status, a large session control, and a quieter settings control using the same
navy/white/lime vocabulary as the existing screen.

Removed the wordmark and kept device/battery information. Replaced stock gray
buttons with 56dp surfaces, 12dp corners, original pause/play/slider vectors,
touch ripple and visible focus stroke. Pause is navy/white; Resume uses the
existing lime accent. Controls is secondary. Added spacing between controls;
weight/padding allow labels to fit at 320dp. Landscape retains its split layout.
Searching/connecting status is shown in the heading while those operations run.
No new animation was introduced.

## Lifecycle change

Opening is now an explicit connection request, including after a previous Pause.
The activity starts the saved ride/host/join mode; without a saved radar, existing
BLE filtered discovery runs after runtime permissions are granted. An already
active service is reused. Pause still stops the service and audio immediately.
It is preserved within the activity and across rotation. Home/Recents return or
a fresh launch starts monitoring again. Motion/presence/boot wake remain disabled.

An activity flag distinguishes an opening from rotation, permission UI and the
association chooser. Rotation saves/restores the flag; user-leave resets it;
permission/chooser flows don't reset it. Resume consumes it (not just onStart),
covering a rapid return where the activity was paused but never fully stopped.
Denied/canceled runtime requests clear pending mode so future openings can retry.
This explicitly supersedes the earlier user preference to retain Pause across
reopening. AGENTS and current app docs now state the new behavior.
