# Varia audio and RideWatch chimes

## Static APK evidence

Same Varia 5.1.3/157 input and provenance as
[protocol report](2026-09-19_apk_protocol.md). Decompiled paths below are under
ignored `artifacts/decompiled/varia/`; no Garmin recording is distributed.

`resources/res/raw/` contains MP3 files for normal/high threats, all-clear,
connection, disconnection and incident detection. `sources/yf/r.java` maps event
classes to these resources; multiple normal/stable/unknown threat classes use
`threat_level_changed_normal_1`, high uses `threat_level_changed_high`, and errors
and disconnect share `remote_device_disconnected`.

`yf/n.java` observes increasing aggregate threat and resets on the no-target
message. `yf/h.java` plays via SoundPool, interrupts lower-priority alerts for
higher ones, and keeps one pending alert. The timed handling windows in `yf/r`
are not all the MP3 duration (all-clear uses a 1489ms window but its file is
about 411ms). `ce/i.java` configures five SoundPool streams with media usage and
sonification content. `ce/k.java` uses transient-may-duck audio focus; `yf/h`
requests it only when its preference is enabled.

## Local signal measurements (not a listening or road test)

Decoded mono at 24kHz with ffmpeg and examined FFT/RMS using numpy. Results in
`artifacts/research/audio/measurements.json`. Normal and high recordings are
1.411 and 1.541 seconds including tails/silence, with strong spectral components
around 523, 698 and 988Hz. High has an additional attack. Connection ascends
approximately 784→988→1175Hz; disconnection reverses that contour. The short
no-target sound has components near 523 and 1046Hz. These are approximate
measurements of layered sounds, not exact oscillator or envelope recovery.

## Independently generated implementation — v0.4

`scripts/generate_alert_tones.py` synthesizes five new PCM WAVs from sinusoids,
a modest harmonic and exponential decay. No original samples are used. They
approximate pitch contour and cadence, not identical timbre or byte-exact audio:

| Event | Pattern | Generated length |
| --- | --- | --- |
| Approach | Two short chord pulses | 500ms |
| Urgent | Three short chord pulses | 680ms |
| Connected | Rising three notes | 500ms |
| Lost | Falling three notes | 500ms |
| Fresh stream becomes empty | Two rising notes | 420ms |

TonePolicy emits on state transitions rather than every packet. An urgent target
wins over a simultaneous connection chime. Loss/error/stale cannot emit an empty
chime. “Empty” means only that a fresh stream has no tracked targets. This preserves
our core's freshness rules rather than inferring safety from silence.

RadarAudio serializes a chime then optional existing TTS, requests temporary
may-duck focus, stops on focus loss, abandons focus on completion, and invalidates
old scheduled speech when a newer event arrives. Focus denial suppresses playback;
it does not force volume or bypass OS routing. The existing service provides the
foreground context required on API36. Both speech and tones use navigation audio
usage. Startup before samples/TTS finish loading can omit an unavailable portion;
old alerts are not replayed after they become available.

Controls → Sound & speech exposes independent tones, speech and experimental
speed switches, plus Test tones. Tones default on; existing speech preference is
preserved. Testing is refused during active monitoring to avoid masking alerts.

Android focus reference:
https://developer.android.com/media/optimize/audio-focus

## Validation and limits

16 tests pass including transitions, escalation/deduplication, every non-live
state, neutral detection and reset. Assembly and lint pass. Generated WAV headers,
lengths and peaks checked (no clipping). API36 emulator installs/opens settings
and the tone-test menu. Urgent test logs show focus=1 (granted) and stream=1
(started), with no focused runtime errors. Emulator had host audio disabled;
this verifies dispatch only. No audible speaker/headphone or music-ducking test on a
physical phone. No physical RVR315 trigger validation. Numeric radar speed is
still experimental. Graphical preview remains visual-only; use Test tones for
manual sound previews.
